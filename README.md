# Ada Currency Converter

A mixed **Ada + C** currency converter with an NCurses terminal UI.  The
application logic is written in Ada; the interactive UI is a C NCurses layer
that Ada calls through `Interfaces.C` bindings.

Enter a source currency, an amount, and a target currency.  The program
fetches the latest exchange rate from
[api.frankfurter.dev](https://api.frankfurter.dev) and displays the result.  A
rolling history of the last 10 conversions is kept in the right-hand panel for
the duration of the session.

The project also serves as a **GNAT SAS static analysis demo** — the history
package contains eight intentional coding issues documented in the source file
header.

---

## Prerequisites

| Tool | Purpose |
|------|---------|
| GNAT Pro (`gcc`, `gprbuild`) | Ada + C compiler and build tool |
| NCurses | UI library — see [NCurses on Windows](#ncurses-on-windows) below; on Linux install `libncurses-dev` (`sudo apt-get install libncurses-dev`) |
| `curl` | HTTP requests at runtime (`sudo apt-get install curl`) |
| GNAT SAS (`gnatsas`) | Ada static analysis |
| CodeSonar (`cs-build`) | C static analysis |

### PATH setup

The GNAT Pro toolchain must appear in `PATH` **before** the GNAT SAS
toolchain, which ships its own `gprbuild` that does not support native
compilation:

```bash
export PATH="/path/to/gnat/bin:$PATH"
```

Add this to your shell profile (`~/.bashrc` or `~/.bash_profile`) to make it
permanent.

### NCurses on Windows

There is no native NCurses on Windows, so it's vendored and built from
source into `third_party/ncurses/install/` (gitignored) before the main
build can link against it:

```bash
bash third_party/ncurses/build.sh
```

This is a one-time step, re-run only if the vendor directory is missing. It
requires `make` on `PATH` — this repo's dev machine uses MSYS2
(`C:\msys64`) solely to provide `make.exe`, since neither GNAT Pro nor Git
Bash ships one. **The script must run under MSYS2's own bash, not Git
Bash's bundled runtime** — mixing the two silently corrupts file I/O between
piped tools. The VS Code task `Vendor: Build ncurses` runs this and is a
dependency of `Build Project`, so building via VS Code handles it
automatically.

## Project structure

```
currency-converter/
├── ada_demo.gpr                  # GNAT project file (Ada + C)
├── default.cgpr                  # Toolchain configuration (generated by gprconfig, machine-specific)
├── Makefile                      # Optional: builds only the C code (for CodeSonar)
├── hub_bf.txt                    # CodeSonar hub bearer token (gitignored, not committed)
├── .vscode/tasks.json            # Build + CodeSonar VS Code tasks (see below)
├── .mcp.json                     # CodeSonar MCP server registration
├── src/
│   ├── ncurses_ui.h              # C declarations for the NCurses UI layer
│   ├── ncurses_ui.c              # NCurses UI implementation (C)
│   ├── currency_ui.ads           # Ada spec — bindings to ncurses_ui.c
│   ├── currency_ui.adb           # Ada body — Interfaces.C wrappers
│   ├── currency_converter.adb    # Main entry point and session loop
│   ├── currency_fetch.adb / .ads # Live rate retrieval via curl
│   ├── currency_history.adb / .ads # Rolling history (GNAT SAS demo)
│   ├── currency_prompts.adb / .ads # Currency-code input with validation
│   └── currency_table.adb / .ads # Supported currency codes and names
├── third_party/ncurses/          # Vendored NCurses source + build script (Windows only)
└── obj/                          # Object files (created by gprbuild)
```

`gprbuild` handles both Ada and C in a single step via `ada_demo.gpr`.  The
`default.cgpr` toolchain file tells `gprbuild` exactly which compilers to use.

The Ada/C boundary is entirely within `Currency_UI`: Ada calls into
`ncurses_ui.c` for all display and input; the rest of the Ada code is
unaware of NCurses.

## Build

### One-time toolchain setup

Generate `default.cgpr` so `gprbuild` knows which compilers to use:

```bash
gprconfig --batch --config=Ada,, --config=C,, -o default.cgpr
```

`default.cgpr` is machine-specific — it's committed, but must be
regenerated whenever you set up a new machine or environment.

On Windows, also run the [NCurses vendoring step](#ncurses-on-windows)
above before the first build.

### Build

```bash
gprbuild --config=default.cgpr -P ada_demo.gpr
```

The compiled binary `currency_converter` is placed in the project root.

### Clean rebuild

```bash
gprclean --config=default.cgpr -P ada_demo.gpr
gprbuild  --config=default.cgpr -P ada_demo.gpr
```

### CodeSonar analysis

Three commands must be run in sequence, wired up as VS Code tasks in
`.vscode/tasks.json`: `CodeSonar: Build Ada` → `CodeSonar: Build C` →
`Analyze Project`. The first two accumulate build information into the same
project directory; the analyze step submits it all to the hub together.

All three require two environment variables to be set **before** VS Code or
Claude Code is launched (both `tasks.json`'s `${env:VAR}` and `.mcp.json`'s
`${VAR}` read from the process environment at launch time, so setting them
in a one-off terminal afterward won't take effect until you restart):

- `CODESONAR_HUB_URL` — e.g. `http://your-hub-host:7340/`
- `CODESONAR_PROJECT_DIR` — a parent directory reused across CodeSonar
  projects, e.g. `C:\Users\you\cso_projects` (build tasks only; the MCP
  server doesn't need this one)

All three also require `-auth bearer -hubbearerfile hub_bf.txt` — a
gitignored token file that must exist at the repo root (not committed) with
a valid CodeSonar hub bearer token.

If invoking `codesonar` from Git Bash directly instead of via the VS Code
tasks, prefix the command with `MSYS_NO_PATHCONV=1`, or Git Bash will mangle
the `-project /CurrencyConverter` argument into a Windows path.

**Full rebuild:** each of the three tasks has a `- Clean` variant
(`CodeSonar: Build Ada - Clean`, `CodeSonar: Build C - Clean`, `Analyze
Project - Clean`). The plain tasks build incrementally; the `-clean` flag on
the Ada step wipes the project's accumulated `prj_files` before rebuilding,
so use the `- Clean` chain when you want a full re-analysis from scratch
(e.g. after changing which sources are included, or if the hub-side project
state looks stale) rather than an incremental update. `-clean` only needs to
run on the first step of the chain — it clears the shared project directory
that both the Ada and C build steps write into.

A `codesonar` MCP server is also registered in `.mcp.json`
(`run_analysis`, `analysis_status`, `list_warnings`) pointed at the same
hub/project, as an alternative to the CLI/VS Code tasks.

## Run

```bash
./currency_converter
```

The NCurses UI occupies the full terminal window and is divided into three
regions:

```
┌─────────────── Ada Currency Converter ──────────────────────────────┐
│ AUD BRL CAD CHF CNY CZK DKK EUR GBP HKD HUF IDR ILS INR ISK JPY   │
│ KRW MXN MYR NOK NZD PHP PLN RON SEK SGD THB TRY USD ZAR            │
├─────────────────────────────────────────┬───────────────────────────┤
│                                         │ Conversion History        │
│  Source currency : ___                  ├───────────────────────────┤
│  Amount in USD   : ___                  │ 100.00 USD -> 92.50 EUR   │
│  Target currency : ___                  │ 50.00 GBP -> 5823.10 JPY  │
│                                         │ …                         │
│  100.00 USD = 92.50 EUR                 │                           │
│  (Rate: 1 USD = 0.925000 EUR)           │                           │
├─────────────────────────────────────────┴───────────────────────────┤
│ Convert another? [y/n]:                                              │
└──────────────────────────────────────────────────────────────────────┘
```

- **Left panel** — active prompts and conversion results.
- **Right panel** — history of the last 10 conversions (newest at the bottom).
- **Status bar** — fetch progress and the continue prompt.

The program exits cleanly when you press any key other than `y` at the
"Convert another?" prompt, restoring the terminal to its original state.

> **Terminal size:** the UI adapts to the actual terminal dimensions but works
> best at 80 × 24 or larger.

## Build and run in VS Code

### Recommended extensions

- **Language Ada** (`AdaCore.ada`) — syntax highlighting, navigation, and
  GNAT SAS integration.

### Building from the VS Code terminal

1. Open the project folder in VS Code (`File → Open Folder`).
2. Open the integrated terminal (`` Ctrl+` ``).
3. Run the build command:

   ```bash
   gprbuild --config=default.cgpr -P ada_demo.gpr
   ```

### Build tasks

`.vscode/tasks.json` is checked in and already wires up the tasks described
above:

| Task | What it does |
|------|--------------|
| `Vendor: Build ncurses` | Windows only — builds vendored NCurses (see [NCurses on Windows](#ncurses-on-windows)) |
| `Build Project` | Default build (`Ctrl+Shift+B`); depends on `Vendor: Build ncurses` |
| `CodeSonar: Build Ada` | First step of the CodeSonar chain |
| `CodeSonar: Build C` | Second step; depends on `CodeSonar: Build Ada` |
| `Analyze Project` | Third step; depends on `CodeSonar: Build C` |
| `CodeSonar: Build Ada - Clean` / `...Build C - Clean` / `Analyze Project - Clean` | Same chain, but wipes accumulated `prj_files` first for a full re-analysis — see [CodeSonar analysis](#codesonar-analysis) |

Press `Ctrl+Shift+B` to run the default build task. Run any other task via
**Terminal → Run Task…**.

### Running from VS Code

Because the program uses NCurses, it must run in a real terminal.  The VS Code
integrated terminal works well.  Launch it directly from the terminal panel:

```bash
./currency_converter
```

Alternatively, add a launch configuration to `.vscode/launch.json` that opens
an external console so the NCurses UI has a proper terminal to work with:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Run currency_converter",
      "type": "cppdbg",
      "request": "launch",
      "program": "${workspaceFolder}/currency_converter",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "externalConsole": true,
      "MIMode": "gdb",
      "preLaunchTask": "Build Project"
    }
  ]
}
```

Press `F5` to build and launch.

## GNAT SAS static analysis demo

Eight deliberate coding issues live in `src/currency_history.adb` and are
described in detail in the comment block at the top of that file.  Running
GNAT SAS on the project will surface all eight:

| # | Issue | Detected by |
|---|-------|-------------|
| 1 | Variable assigned but never read (`Last_Rate`) | GNAT `-gnatwm` + SAS |
| 2 | Self-assignment with no effect (`H(10) := H(10)`) | GNAT `-gnatwr` + SAS |
| 3 | If statement with no effect (condition always true) | GNAT `-gnatwr` + SAS |
| 4 | Variable that could be constant (`Count`) | GNAT `-gnatwk` + SAS |
| 5 | Potentially uninitialised variable (`Prev_N`) — **cross-unit, path-sensitive** | GNAT SAS only |
| 6 | Redundant intermediate variable (`I`) | Code quality observation |
| 7 | Magic numbers (`10`, `9`, `1`) | GNAT SAS (with config) |
| 8 | Non-descriptive identifiers (`H`, `N`, `I`, `F`, `T`) | GNAT SAS (with config) |

Issue 5 is the headline finding: because `Add_To_History` is a separate
compilation unit, GNAT SAS propagates the uninitialized-read finding to every
call site in `currency_converter.adb`, demonstrating inter-unit, path-sensitive
data-flow analysis that the compiler alone cannot perform.

On the C side, `ncurses_ui.c`'s `draw_chrome` intentionally keeps a raw
`strlen()` call on a `const char *` as a CodeSonar-demoable finding
(`BADFUNC.BO.STRLEN`).

**None of these are real defects — do not "fix" them.** They're the point
of the demo; treat anything CodeSonar/GNAT SAS surfaces here as expected
output, not cleanup work.
